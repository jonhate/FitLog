# FitLog V1.3.2 故障修复与验证

日期：2026-10-10（用户所在时区）。

## 实际故障与根因

用户反馈开始训练与历史查看/编辑失败，报错 `no such column: ss.side`。原迁移用同一行发送 `INSERT ...; DROP TABLE ...; ALTER TABLE ...;`。Android 插件 `UtilsSQLite.getStatementsArray` 只按分号紧接换行切批次，SQLCipher `execSQL` 只执行首条语句，因此临时组表已有副本，但原组表未替换，数据库版本号已被标为3。浏览器内存SQLite与better-sqlite3原有测试可执行完整批次，未覆盖该差异。

## 修复

- 原生适配器逐条发送SQL，不再依赖插件的批次分隔规则。
- 打开数据库时检查实际列结构，不单凭版本号判断升级完成。
- 对版本号3但缺列的旧表先写入并同步保护快照，再事务修复。旧组表是权威来源，临时副本另外收录于保护快照，原有记录、草稿与ID保留。
- 表结构、引用与完整性检查通过后才提交版本。保护备份或迁移失败即停止，不清空数据库。
- 移除“补全空白日期的示例动作”按钮。
- 休息日显示“今日休息”并引导选择其他日期，空计划需先添加动作。取消休息状态恢复原动作和训练入口。
- 完整JSON恢复入口明确标注覆盖，提醒会替换全部当前计划、历史和草稿，备份导出后的新增记录也会被覆盖。不将它当作查看历史或升级修复操作。
