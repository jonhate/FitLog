# FitLog V1.3.4｜训前热身与训后拉伸开发交接

## 目标与技术现状

目标仓库：`jonhate/FitLog`，基线为 V1.3.3。当前框架 React + TypeScript + Vite + Capacitor Android，本地原生 SQLite；七张表，数据库版本 v3。相关现有文件：`src/main.tsx`、`src/style.css`、`src/schema.ts`、`src/db.ts`、`src/service.ts`、`tests/fitlog.test.ts`。不要修改现有组数、重量继承、左右手训练、计划快照和历史编辑规则。

本功能定义为**计划选配的辅助训练模块**。每个模块是“计划中的文字动作清单 + 本次训练是否完成”的组合；不记录重量、次数、RIR、组数，不占用力量训练进度与统计，也不强制勾选才能结束训练。

## 必须实现的交互

### A. 每日计划编辑页

- 训练名称输入框之后、**设为休息日**开关**之前**，横向或响应式换行显示两个独立开关：`训前热身`、`训后拉伸`。
- 开启任一选项后，在该选项下出现内容卡片，卡片支持独立展开/收起；启用状态**不等于**完成状态。
- 内容卡片中的动作清单允许编辑，使用一个多行文本框即可，不需要复杂的动作/组数编辑器。切换关闭时保留上次填写的文本；重新开启无需重填。
- 首次启用且文本为空时，按训练日自动填入下方默认内容；用户可以随时修改。
- 切换设为休息日后，保留配置，但该日不能开始力量训练，因此不会生成/显示这两个训练模块；取消休息日可继续使用原配置。
- 复制其他日期计划时，将该日热身与拉伸的开关和内容一起复制。
- 计划保存校验：文本为字符串，最长建议 2000 字；保存失败提供错误提示而不是静默丢失。

### B. 正在进行的训练页

布局次序严格为：

1. 页面标题与原有训练进度；
2. `训前热身`（若计划开启）；
3. 原有所有正式力量训练动作；
4. `训后拉伸`（若计划开启）；
5. 本次训练备注、临时动作与完成训练按钮（保留原有操作逻辑；若原有备注布局在此之外，仅要求拉伸在力量动作之后且完成训练按钮之前）。

- 热身/拉伸模块都能展开与收起；默认展开，用户可收起。
- 内容以简洁清单或保留换行形式呈现。
- 每个模块底部唯一可交互完成框：`已完成热身`、`已完成拉伸`；默认未勾选。
- 勾选后立即写入本地 SQLite；再次点击可取消；写入失败显示错误，不得虚假显示已保存。
- 完成勾选不能作为原有“完成训练”的硬条件，不能改变总组数、完成组数和RIR统计。
- 开始训练时将开关和内容保存为**本次训练快照**；此后修改周计划不得回改已经开始的训练或历史。

### C. 历史页

- 查看历史时按同样顺序显示两模块、文字快照和完成状态。
- 历史编辑时允许修改这两个“完成”勾选；和现有历史修改流程一致，先在页面中改草稿，点击“保存历史修改”后才持久化；放弃修改不应污染数据库。
- 历史不出现的模块不要显示“未完成”。旧历史一律默认两个模块均未启用，而不是事后判断其是否做过。

## 建议的 SQLite 设计（v3 → v4）

`plans` 新增：

- `warmup_enabled INTEGER NOT NULL DEFAULT 0 CHECK(warmup_enabled IN(0,1))`
- `warmup_text TEXT NOT NULL DEFAULT ''`
- `stretch_enabled INTEGER NOT NULL DEFAULT 0 CHECK(stretch_enabled IN(0,1))`
- `stretch_text TEXT NOT NULL DEFAULT ''`

`sessions` 新增：

- `warmup_enabled INTEGER NOT NULL DEFAULT 0 CHECK(warmup_enabled IN(0,1))`
- `warmup_text TEXT NOT NULL DEFAULT ''`
- `warmup_completed INTEGER NOT NULL DEFAULT 0 CHECK(warmup_completed IN(0,1))`
- `stretch_enabled INTEGER NOT NULL DEFAULT 0 CHECK(stretch_enabled IN(0,1))`
- `stretch_text TEXT NOT NULL DEFAULT ''`
- `stretch_completed INTEGER NOT NULL DEFAULT 0 CHECK(stretch_completed IN(0,1))`

解释：配置与完成分开；计划文字作为 session 快照；completed 只反映本次训练。不要放进 `session_sets`，也不要借用 `session_exercises`，以免污染肌力记录。建议从 `src/schema.ts` 引入 v4 的迁移字段列表，在 `src/db.ts` 中做幂等的 `ALTER TABLE`，升级前的备份、事务、完整性检查沿用既有机制。修复部分升级失败时的重复执行应安全。

### 备份兼容（高优先级）

- 完整 JSON 导出包含 v4 新字段；完整 JSON 恢复支持 v1/v2/v3/v4 备份。
- 旧备份缺少的 v4 字段使用上述默认值补齐，不清空既有组数/历史，也不更改原始 UUID、动作关系和侧别。
- 完整恢复依然是**明确确认后的全量替换**；本功能不能悄悄调用恢复流程。
- 计划专用 JSON 导入支持可选新模块字段。若旧格式未提供字段，默认关闭，保留之前“只替换指定日期计划、不触及历史与进行中训练”语义。
- CSV 若加新状态字段，新增两列 `训前热身完成`、`训后拉伸完成` 并保持原列不变。数据库概览的完成组统计不受影响。

## 按训练日推荐的默认提示内容

以下热身组均为**正式力量训练组以外**的递增热身，不计入训练总组数。

| 训练日 | 训前热身（约8–12分钟） | 训后拉伸（约5–8分钟） |
|---|---|---|
| 周一、周六 胸肩三头 | 快走3分钟；肩关节绕环10次；弹力带拉开12次；轻量俯卧撑8次；卧推2–3组递增热身 | 门框胸肌拉伸左右各20–30秒；三头过顶拉伸左右各20–30秒；肩后侧拉伸左右各20–30秒，按需重复 |
| 周二、周五 背部 | 快走3分钟；肩胛控制10次；弹力带划船12次；胸椎旋转左右各8次；首个划船/下拉动作1–2组轻重量热身 | 凳上背阔肌拉伸20–30秒；肩后侧拉伸左右各20–30秒；轻柔胸椎旋转，按需重复 |
| 周四 腿部 | 轻松步行3分钟；前后摆腿左右各10次；臀桥12次；徒手深蹲10次；腿部主项2–3组递增热身 | 髋屈肌拉伸左右各20–30秒；股四头肌拉伸左右各20–30秒；腘绳肌拉伸左右各20–30秒，按需重复 |
| 周三、周日 | 默认为休息日；两个选项默认关闭，可自行编辑后作为其他训练日使用 | 同左 |

## 验收清单（必须过）

1. 编辑页面两个选项在“设为休息日”**上方**；分别启用、关闭、展开、收起无错。
2. 训练页面热身在第一个正式动作前、拉伸在最后一个正式动作后，均有独立完成勾选；刷新和强制停止后状态仍在。
3. 已开始训练后修改计划，进行中训练及历史文本快照不变。
4. 勾选热身/拉伸不改变力量进度、完成组数、重量继承、历史记录和单侧动作逻辑。
5. 两项未勾选，正式动作做完后仍可完成训练。
6. 设为休息日不能开始训练；切回训练日后此前文字设置保留。
7. 复制日计划能复制两个模块的内容；旧计划专用导入仍能成功。
8. v3 真机数据库升级到 v4 时保持原有历史、草稿和计划；升级前备份可靠。
9. v1/v2/v3/v4 完整 JSON 恢复均通过；旧备份默认禁用新模块；导出再恢复数据一致。
10. Vitest、Playwright、前端构建、Capacitor 同步和 APK 构建验证，尤其检查 Android 真机输入/持久化；构建成功不等于设备验收。
11. 发布 APK 前确认与已安装包相同 `com.jon.fitlog` 和签名：如果没有原签名文件，不声称可直接覆盖安装。不得生成 0KB 伪 APK。
