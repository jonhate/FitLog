# 手机端验收清单（尚未执行）

本环境未连接真实 Android 手机，也未安装可用模拟器；无 KVM 加速设备。下面的手机端行为仍需实测，不能以浏览器测试代替。

1. 安装 APK；断网后打开。选择示例计划。日期与星期按本地显示。
2. 编辑周一，将平板卧推设为 4 组，默认重量依次 30/35/40/30；保存。
3. 开始周一训练。首次无历史时默认应是 30/30/30/30，符合“上一组优先于计划”规则。
4. 手动记录本次实际 30/35/40/30，各组 12 次、RIR2，分别完成，等待“已保存”。
5. 关闭应用、重新打开；第一组及其他已提交组应存在。对草稿有效输入进行同样检查。
6. 在 Android 设置中强制停止应用，再打开；重启手机后重复；输入和完成状态应保留。
7. 完成其他动作，或跳过未做动作。完成训练。再开始一次周一训练，应继承 30/35/40/30；次数、RIR与完成状态为空/未完成。
8. 新增第5组应继承第4组。手动改第2组不得覆盖历史默认的第1/3/4组；已经完成组不得被级联改写。
9. 修改周一计划，再查看原历史；快照与成绩不变。当天第二次训练不覆盖第一次。
10. 修改历史重量，明确保存；未来新训练读取更新值，已有草稿不重算。
11. 测试删除组、跳过动作、临时动作、顺序调整、复制周计划和休息日选择其他计划。
12. 检查系统返回：子页面返回列表；未保存历史/计划有确认；根页返回退出。
13. 检查软键盘不遮挡当前输入；屏幕 360/393px 等尺寸无横向溢出。
14. 设置→导出JSON→系统保存界面选择手机本地 Documents。用独立文件管理器确认文件存在并可读取。
15. 导出CSV；用电子表格软件确认中文、重量小数、RIR和特殊字符正确。
16. 先保存JSON，另建几条测试记录；完整替换恢复先前备份，数量和逐组内容应匹配。
17. **只有确认独立JSON文件可读取后**，才在测试数据上执行清除应用数据或卸载重装，再从 Documents 恢复，验证计划、历史与草稿完整。
18. 导入非法JSON、错误版本、错误引用的备份；提示失败且当前数据不变。
19. 在真实设备上安装含测试数据的schema v1工程，再升级当前APK，确认迁移保留历史并生成迁移保护快照。
20. 测试取消保存、不可写目录、存储空间不足与进程在文件选择期间被终止；不能误报导出成功。

验收记录：设备型号、Android/WebView版本、日期、通过/失败项目与错误信息。上述全部当前标记为“未验证”。

V1.3 补充（全部未验证）：

21. 旧版先导出独立 JSON，再直接覆盖安装 V1.3。原计划、历史和草稿内容及 ID 应保留；旧左右分开的动作不应自动合并。
22. 新计划设为单侧，第1组左10kg/右12kg。训练每组有两行，左侧完成后进度不增加，左右均完成才增加1组。强停、重启后两侧草稿及状态完整。
23. 完成一次单侧训练，再创建新训练，左右重量独立继承；新增一组读取各侧上一组，删除一组同时删除两侧。双手旧记录不被用作单手历史。
24. 本次感受自动保存；历史修改感受必须明确保存。下次提醒在新训练显示，但不自动改重量、不改已有历史快照。
25. 目标次数默认不必填写；固定次数只有一个输入，范围有明确最少/最多标注。训练展示目标，实际次数为空。
26. 单侧、备注、提醒和独立默认重量完整JSON恢复；CSV每个侧别一行，左右组号相同；概览与进度按逻辑组计数。

27. 在旧组表缺side、版本号却为3的故障安装上直接覆盖V1.3.2，确认保护快照和表结构修复，原记录逐字段保留，历史可以查看编辑，开始训练可用。不得先清除应用数据或用旧JSON覆盖。
